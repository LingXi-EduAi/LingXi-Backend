## 三、代码与需求复核

- 未修改原有教学业务表，未增加物理外键。

### 3.2 BE-09 持久化主链路

- `POST /api/ai/tasks` 能创建本地任务和子任务，并立即返回本地 `taskId`、`conversationId`、初始状态和 `eventUrl`。
- Chatflow 后台执行不依赖浏览器持续连接。
- 任务事件先写入数据库，提交事务后再通过 SSE 广播。
- 任务和子任务最终状态一致，任务结果能够写入并通过快照接口读取。
- 状态机、乐观锁、事件 sequence、事件幂等和异常处理已有自动化测试覆盖。

### 3.3 BE-07 控制与续传

- 任务快照、SSE 订阅、停止任务和子任务重试接口均已实现。
- `Last-Event-ID` 使用 `{taskId}:{sequence}` 格式。
- SSE 补发和实时事件通过 sequence 排序并去重。
- 跨用户任务统一隐藏为 404。
- 终态任务不能再次被停止，返回 409。
- 停止、重试上限、依赖检查和并发状态已有自动化测试覆盖。

### 3.4 鉴权响应契约修复

发现新 AI 接口缺少 Token 时，响应中的 `data: null` 会被 Fastjson 默认省略。修复后仅对 `/api/ai/tasks/**` 的鉴权错误启用 null 字段序列化。

修复后的响应结构：

```json
{
  "status": 401,
  "msg": "参数缺少 token 值",
  "requestId": "非空请求标识",
  "data": null
}
```

旧接口仍保持原响应结构：

```json
{
  "msg": "参数缺少 token 值",
  "status": 1000
}
```
