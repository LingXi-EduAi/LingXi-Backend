## 验证技术路线

代码提交 → 后端单元测试和 Mapper 测试 → 前端 store/SSE/组件测试 → Mock Dify 集成测试 → MySQL/Redis 环境测试 → 浏览器 E2E（登录→创建→流式→停止/刷新→历史）→ SSE 并发/长连接压测 → staging 部署 → 数据库迁移 verify → 生产演练 → 发布签字。

故障定位顺序：先确认提交号和环境变量 → 检查认证/权限 → 检查本地任务和数据库状态 → 检查 Dify 原始事件 → 检查事件适配和 SSE → 最后判断浏览器组件渲染问题。每个缺陷必须标注代码、配置、数据或外部平台归属。

## 发布验收

- 所有构建和测试命令有日志证据。
- 云 MySQL 迁移完成并通过 verify。
- Redis、Dify、Nginx 和后端端口可用。
- SSE 不被代理缓冲或超时截断。
- 构建产物、日志、截图和导出文件无密钥及 PII。
- 演示账号、数据清理、回滚和现场应急步骤可重复执行。
