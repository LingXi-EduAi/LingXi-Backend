## 实施顺序

1. 冻结请求/响应、事件和数据库契约。
2. 先完成任务、会话、消息和事件主链路。
3. 接入真实 Dify 样例，完成证据和 usage 字段映射。
4. 完成配置、限流、隐私、审计和上传能力。
5. 通过单测后再进行前端联调和云端迁移。

## 端到端技术路线

```text
HTTP 请求
  -> AuthorizationInterceptor 解析 token 和用户
  -> AiTaskController / AiConversationController
  -> AiTaskService / AiConversationService
  -> Mapper 持久化本地任务、会话和消息
  -> AiTaskExecutionService 调用 DifyGateway
  -> DifyEventAdapter 转换为 LingXiEvent v1
  -> TaskEventBroadcaster 推送 SSE
  -> AiTaskResultPersistenceService 写入消息/证据/结果
  -> AiModelCallLogService 异步记录 usage 和耗时
```

任务创建链路：校验用户和请求 → 创建本地 task/subtask → 生成 conversation 关联 → 异步执行 → 保存 Dify task/conversation ID → 广播事件 → 终态写入 answer、evidence 和错误信息。

会话继续链路：校验本地 conversation 所有权和未删除状态 → 使用本地 `conversationId` 创建下一任务 → 后端解析对应 Dify conversation ID → 复用同一会话执行；前端和外部调用方不得直接使用 Dify ID。

失败链路：Dify 异常或事件错误 → 统一错误事件 → 更新任务/子任务状态 → 保留可诊断错误码 → 清理运行时注册表；仅满足依赖和重试次数条件的失败子任务允许重试。

## 验收标准

- 所有受保护资源均校验当前用户所有权。
- SSE 支持心跳、断线恢复、停止和重复事件幂等。
- 会话删除不误删其他用户数据，继续对话只接受本地会话 ID。
- 真实 Dify 事件能映射最终回答、引用、模型和 usage。
- 数据库迁移可重复验证，失败可回滚。
- `mvn clean test` 通过，异常不泄露密钥或 PII。

## 外部输入

算法组必须提供 `ALG-01` 至 `ALG-07` 样例；部署人员必须提供云端迁移 `verify` 结果；需求方必须冻结附件、教师日志可见范围和保留期限。
