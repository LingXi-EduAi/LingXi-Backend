## 职责边界

- 维护三个仓库的版本基线、分支规则和发布标签。
- 维护 API、LingXiEvent、数据库迁移和环境变量的变更流程。
- 决定新 AI 链路与旧兼容接口的边界，不让前后端绕过统一入口。
- 维护任务状态、负责人、验收证据和文档入口。
- 处理跨仓库冲突、重大技术决策、回滚和风险升级。

## 技术路线

需求或缺陷 → 建立/更新 ADR → 拆分 A-F 任务 → 登记接口/事件/迁移影响 → 创建功能分支 → 实现与测试 → PR 评审 → 跨仓库联调 → 发布验收 → 固化提交号和交接记录。

跨仓库变更必须按以下顺序落地：

1. 后端先定义 DTO、响应、事件或数据库变更。
2. 在 `07-跨仓库接口与任务矩阵.md` 登记前后端映射。
3. 前端按契约实现 store、组件和错误状态。
4. 算法侧提供真实事件或配置版本。
5. QA 使用固定版本执行联调和回归。
6. 架构负责人确认兼容性、回滚点和文档状态。

## 实施要求

1. 每个任务必须有唯一主责人和验收人。
2. API、事件或 DDL 变化必须先登记接口索引或 ADR。
3. 跨仓库功能拆成后端、前端、联调三个任务，并固定提交号。
4. 主分支只接受构建和测试通过的提交。
5. 文档、任务卡和验收证据必须与代码提交同步更新。

## 验收标准

- 三仓库基线可复现，工作区状态清晰。
- 任务看板不存在无主任务、重复编号或过时负责人。
- 任一 API 变更可追溯到任务、提交和测试证据。
- 旧文档仍可访问，但明确标记为历史参考。

## 交接物

- 基线同步记录；
- ADR 或变更说明；
- 接口矩阵更新；
- 验收签字和回滚点；
- 下一责任人的待办清单。
