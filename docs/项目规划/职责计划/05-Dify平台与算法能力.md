必须提供并说明 `ALG-01` 至 `ALG-07`：最终回答/message ID、引用路径、Workflow 输出、输入结构、错误/429、usage/模型字段。

## 版本与交接要求

- 每次 Prompt、知识库或工具变更记录版本、时间、负责人和回滚方式。
- 样例必须脱敏，不包含真实用户凭据或隐私数据。
- 样例必须能由后端测试或联调脚本复现。
- Dify 配置完成后，交接给后端字段映射和前端展示验收。

## 端到端技术路线

```text
用户查询
  -> 后端 AiAgentRouter 选择应用/Agent
  -> AiConfigService 解析当前激活配置
  -> DifyGateway 注入服务端 API Key 和稳定 user 标识
  -> Chatflow/Workflow 执行
  -> Dify SSE/完成事件
  -> 后端 DifyEventAdapter
  -> LingXiEvent、ai_message、ai_evidence、ai_model_call_log
  -> 前端工作台、时间线、证据和教师分析
```

配置实施顺序：先建立最小可复现 Chatflow → 配置调度 Agent → 加入反思/评价 Agent → 建立知识库和引用 → 增加工具调用 → 固定结构化输出 → 提供脱敏样例给后端和 QA。

事件交接必须说明：原始 event 名称、字段路径、是否增量、唯一 ID、终态条件、失败/限流含义、后端目标字段和前端展示组件。

## 验收标准

- 学科、调度、反思链路可在 Dify 后台复现。
- RAG 回答带可追溯来源，字段能被后端落库。
- 工具调用有输入、执行痕迹和结果。
- 失败、限流和超时事件能被前端安全展示。
