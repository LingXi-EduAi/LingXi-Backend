## 一、我们到底要做什么（一句话）

做一个**多智能体协同学习系统**：学生提问，系统里好几个 AI 分工干活——**总指挥**把问题拆成小任务，分给**各科老师 AI** 解答，**批改老师 AI** 检查答案质量，最后把"答案 + 出处 + 思考过程"一起展示给学生，老师还能看学生的学习情况。

## 二、最终系统长什么样（做完的样子）

| 谁用 | 能干什么 |
|---|---|
| **学生** | 提问 → AI 边想边答（文字逐字蹦出）；看到答案引用的资料出处；看到 AI 的思考过程时间线；历史对话刷新不丢；答完收到"薄弱点 + 推荐练习" |
| **老师** | 看每个学生/任务的 AI 调用统计（花了多少 token、多久答完）；回放某次 AI 回答全过程；查看模型调用日志（比赛硬性材料） |
| **管理员/开发** | 隐私合规（手机号等打码、操作留痕、数据可删）；防刷限流；Dify 应用版本可后台切换不用改代码 |

**技术底子**（不用懂，知道就行）：Vue3 前端 + Spring Boot 后端 + MySQL 存数据 + Redis 做缓存/限流 + Dify 平台跑 AI。**浏览器不直接碰 AI 平台**，全部走后端中转——这是安全要求，也是评审加分项。

## 四、方案确定版（已拍板的决定）

1. **技术栈不动**：Vue3 + Spring Boot + MySQL + Redis + **Dify**。
2. **初赛冻结 Dify**：有人质疑 Dify 过时，但初赛只剩 8 天、后端已投产，**不换平台**。改进诉求（AI 自编排等）留到 Part B 的 DIFY-04~07 解决，决赛后再评估是否迁移。
3. **三阶段节奏**：
   - **Part A（08-18→08-27）初赛冲刺**：能跑通演示 + 录视频 + 写报告（31 任务，约 27 人天）
   - **Part B（08-28→10-10）完整实施**：隐私/日志/教师分析/反思反馈/知识库全科化（27 任务，约 30 人天）
   - **决赛（10-10→中旬）**：优化报告 + 答辩 PPT + 加固
4. **砍单红线**：前端工作台、认知轨迹、演示数据、演示视频、知识库 RAG **绝不砍**；会话侧栏、日志导出可砍（时间不够时）。

## 五、术语对照表（技术黑话 → 大白话）

| 术语 | 大白话 |
|---|---|
| **Agent / 智能体** | 一个专门干某类活的 AI。学科 Agent = 各科老师；调度 Agent = 总指挥；反思 Agent = 批改老师 |
| **多智能体** | 多个 AI 分工协作（不是一个大杂烩聊天机器人） |
| **SSE（流式输出）** | AI 边想边答，文字一个字一个字蹦出来（不用等全部生成完） |
| **RAG / 知识库** | 先上传教材/资料建库，AI 回答时先查资料再答，**答案带出处**（防止瞎编） |
| **Token（模型调用量）** | AI 回答一次消耗的"字数单位"，比赛材料要记录它 |
| **API / 接口** | 程序之间对话的约定：前端说"我要这个"，后端给什么 |
| **鉴权 / 认证** | 登录校验：证明"我是谁"才能访问 |
| **路由守卫** | 页面访问权限：学生不能进老师页面 |
| **Token（登录凭证）** | 登录后发的一张"门票"，每次请求带着它 |
| **幂等** | 同一操作重复提交也不会出错（比如重复点两次发送） |
| **乐观锁** | 防止两个人同时改同一条数据打架 |
| **归一化状态** | 页面数据统一管在一处，不各写各的（避免数据对不上） |
| **种子数据** | 提前造好的演示数据（录视频用的假会话） |
| **代理层 / 中转** | 浏览器 → 我们后端 → AI 平台，**不直连**（安全要求） |
| **iframe** | 网页里嵌的另一个网页 |
| **脱敏** | 打码：手机号/邮箱显示成 **** |
| **限流** | 防刷：一分钟最多调 N 次，超了提示"稍后再试" |
| **审计日志** | 操作留痕：谁在什么时候干了什么 |
| **压测** | 压力测试：模拟很多人同时用，看会不会卡 |
| **E2E 测试** | 自动模拟用户从头用到尾走一遍完整流程 |
| **覆盖率** | 测试覆盖了百分之多少的代码（比赛材料好看，但真实最重要） |
| **迁移脚本** | 建表/改表结构的 SQL 文件（版本化，可回退） |
| **执行管线** | 任务从创建到完成的全流程处理（拆任务→分派→回答→入库） |
| **网关** | 所有 AI 请求统一进出的大门（统一记日志、统一转发的必经之路） |
| **工作流** | Dify 里编排 AI 干活步骤的流程图 |
| **子任务** | 总指挥把大问题拆成的小任务 |
| **认知轨迹 / 轨迹回放** | AI 思考过程展示（比赛演示亮点，证明"AI 不是黑箱"） |
| **证据 / 引用来源** | 答案是从哪本书/哪份资料来的 |
| **防幻觉 / 边界提示** | 防止 AI 一本正经胡说八道：没把握时明说"不确定，建议老师确认" |
| **置信度** | AI 对自己回答的把握程度（低 → 显示警告） |
| **会话** | 一次对话（历史记录按会话存） |
| **反馈闭环** | 答完题 AI 给"薄弱点 + 推荐练习"（大创"个性化反馈"评审点） |
| **生产环境** | 正式对外服务的服务器（不是自己电脑） |
| **回滚** | 出问题退回上一个可用版本 |
| **实体类 / Mapper** | 一张数据库表对应的 Java 代码（存数据/取数据） |
| **vitest / surefire** | 前端/后端的测试工具（保证改代码不弄坏旧功能） |
| **Playwright** | 能自动点页面、填表单的测试机器人 |
| **AI 任务工作台** | 学生和 AI 对话的主页面 |
| **教师分析页** | 老师看学生 AI 学习情况的统计页面 |
