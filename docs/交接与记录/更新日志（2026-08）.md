# 更新日志（2026-08）

更新日期：2026-08-09

## SEC-01：安全配置修正

- 修正 `application.properties` 中缺失的注释前缀。
- 数据库、Redis、短信服务和 Dify 凭据继续通过 `.env` 环境变量提供。
- 前端不保存或发送 Dify API Key。

## BE-01：统一 DifyGateway

- Chatflow、Workflow、文件上传、语音转文字和会话操作统一通过 `DifyGateway` 调用 Dify。
- Controller 和 Service 不再自行创建 Dify HTTP 客户端或拼接 Bearer 鉴权。
- 旧版 `/api/**` 接口保留兼容，但内部同样通过 `DifyGateway` 转发。
- Chatflow 与 Workflow 真实调用验证成功。

## BE-02：统一 AI 任务接口

- 新增 `POST /api/ai/task`，作为当前统一 AI Chatflow 任务入口。
- 新增 `AiTaskController`、`AiTaskService` 和 `AiTaskServiceImpl`。
- 请求字段为 `query` 和可选的 `conversationId`。
- 响应返回 `answer`、`conversationId`、`messageId` 和 `elapsedMs`。
- 当前接口使用阻塞模式；任务持久化、SSE、停止和重试不在本阶段实现。
- 详细契约见 [AI任务接口契约-v1.md](../接口与协议/AI任务接口契约-v1.md)。

## BE-03：登录用户映射

- 后端从登录 Token 获取当前用户 ID，并将其作为 Dify `user`。
- Chatflow、Workflow、统一 AI 任务接口和旧兼容接口均不接受前端指定 Dify user。
- 修复旧 `/api/test` 使用固定 `user_123` 的问题。

## BE-04：会话所有权校验

- 会话列表强制按当前登录用户过滤。
- 会话详情、编辑、删除和重命名操作增加所有权校验。
- 编辑会话时强制使用登录用户 ID，不能通过请求体修改 `studentId`。
- 非会话所有者不能修改或删除其他学生的会话。

## BE-05：冻结 LingXiEvent v1 协议

- 新增 `LingXiEvent` 公共事件结构，固定 `eventId`、`sequence`、`eventType`、`taskId`、`conversationId`、`occurredAt`、`status`、`payloadVersion` 和 `payload` 字段。
- 固定 v1 事件类型：任务开始、任务拆解、Agent 分配、节点进度、检索完成、校验完成、答案增量、任务完成和任务错误。
- 明确每类事件 payload 的必需和可选字段，并纳入完整任务状态集合。
- 提供任务开始、答案增量和任务失败示例，详细内容见 [LingXiEvent协议-v1.md](../接口与协议/LingXiEvent协议-v1.md)。

## BE-06：Chatflow SSE 流式代理

- 保留现有阻塞接口 `POST /api/ai/task`，新增 `POST /api/ai/task/stream`，避免改变已冻结的 BE-02 响应契约。
- DifyGateway 使用 `response_mode=streaming` 调用 Chatflow，并将 SSE 数据转换为 LingXiEvent 后通过 `SseEmitter` 返回前端。
- 每个流式请求生成独立的灵犀 `taskId`，事件序号从 1 开始；正常完成只发送一个 `task_finished`，Dify 错误转换为 `task_error`。
- 使用 SSE 注释心跳维持连接，默认心跳间隔为 15 秒，连接超时默认为 10 分钟；可通过 `.env` 中的 `AI_SSE_HEARTBEAT_MS` 和 `AI_SSE_TIMEOUT_MS` 调整。
- 浏览器断开、连接超时、正常完成和上游错误均取消 Dify OkHttp Call 并停止心跳调度，避免连接和线程泄漏。
- 流式连接使用独立的 `DIFY_STREAM_CONNECT_TIMEOUT_MS`、`DIFY_STREAM_READ_TIMEOUT_MS` 配置；读超时默认为 0，由 SSE 超时统一控制。
- 后端响应增加 `Cache-Control: no-cache` 和 `X-Accel-Buffering: no`，防止浏览器或 Nginx 缓冲事件。

### BE-06 接口边界说明

- 当前 `POST /api/ai/task/stream` 是直接流式代理，`taskId` 仅在本次连接期间有效，事件尚未写入数据库。
- 暂不提供 `GET /api/ai/tasks/{taskId}/events`、Last-Event-ID 续传、停止和重试；这些能力分别依赖 BE-07 至 BE-09 的任务状态和事件持久化。
- 不能在本阶段用内存任务表替代数据库，否则后端重启或多实例部署会造成事件丢失和任务归属不一致。最终异步任务接口必须在持久化能力完成后再发布。
- 实际联调曾发现 `ResponseEntity<?>` 包装 `SseEmitter` 会触发 Spring MVC JSON 转换器错误（`No converter for SseEmitter`），已改为 Controller 直接返回 `SseEmitter`，并通过 `ResponseStatusException` 处理参数错误。
- 原生 `EventSource` 只支持 GET，不能携带本接口需要的 POST JSON 和 Token Header；前端必须使用 `fetch + ReadableStream`。Nginx 部署必须配置 `proxy_buffering off`，且 `proxy_read_timeout` 应大于 `AI_SSE_TIMEOUT_MS`。

## BE-09：AI 任务与事件持久化

- 新增 `POST /api/ai/tasks`，按 `CHATFLOW` 或 `WORKFLOW` 创建本地任务与会话，立即返回 `taskId`、`conversationId`、`status`、`eventUrl` 和 `requestId`，旧接口保持不变。
- 任务在独立线程池持续执行，浏览器连接不再决定任务生命周期；Chatflow 和 Workflow 均使用 Dify streaming，并登记本实例运行句柄。
- `AiEventService` 锁定任务行分配数据库 sequence，以乐观锁更新状态，在同一事务写入事件和子任务，事务提交后才广播；Dify 可识别的外部事件 ID 用于幂等。
- 持久化 `task_started`、`task_decomposed`、`agent_assigned`、节点进度、回答分片、完成和异常；终态不可被后到事件覆盖。
- 服务启动时把遗留 `RUNNING` 任务转为可重试的 `FAILED`，写入 `execution_interrupted`，并对已知 Dify task ID 尽力停止。
- 真实联调验证：Chatflow 长回答持久化 35 个回答分片及 584 字完整结果；Workflow 连续持久化 36 个事件和 outputs，两类任务最终均为 `SUCCEEDED`，测试数据已清理。

## BE-07：AI 任务控制与事件续传

- 新增任务快照、SSE 事件订阅、停止和失败子任务重试接口；跨用户任务与子任务统一返回 404，新接口错误响应统一包含 requestId。
- `Last-Event-ID` 固定为 `{taskId}:{sequence}`：先注册实时订阅并缓冲，再补发数据库事件，最后按 sequence 去重排空，浏览器断开仅移除订阅者。
- 停止操作先在事务内将 `RUNNING` 写为 `STOPPED` 并生成 `task_finished/user_stopped`，提交后再取消本地 Call 和尽力调用 Dify stop；重复停止幂等，其他终态返回 409。
- 子任务仅允许 `CHATFLOW`、`WORKFLOW` 的失败执行重试；校验依赖、并发状态和最多 3 次限制，复用原 subtask 并递增 executionNo/retryCount，旧执行事件不覆盖。
- 真实联调验证：从 sequence 5 连续续传至 153；停止后任务与子任务保持 `STOPPED`；失败 Workflow 三次重试后 executionNo=4、retryCount=3，第四次返回 409，全部测试数据已清理。
