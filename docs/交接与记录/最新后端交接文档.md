## 2. 新增接口

请求都需要 Header：`token: <灵犀登录 Token>`。

### AI 会话

```text
GET    /api/ai/conversations?currentPage=1&pageSize=20
GET    /api/ai/conversations/{conversationId}/messages?currentPage=1&pageSize=20
PATCH  /api/ai/conversations/{conversationId}
DELETE /api/ai/conversations/{conversationId}
```

重命名 Body：

```json
{"title":"新的会话标题"}
```

删除是本地软删除，不删除任务、事件、消息和 Dify 远端数据。跨用户资源统一返回 404。

### 模型调用日志（教师权限）

```text
GET /api/ai/model-calls
GET /api/ai/model-calls/export?format=csv
GET /api/ai/model-calls/export?format=json
```

支持 `taskId`、`nodeName`、`startAt`、`endAt`、`currentPage`、`pageSize` 过滤。当前实现按登录教师的 `user_id` 过滤；教师查看学生任务的范围尚未确认，不能把当前接口当作全体学生统计接口。

## 3. BE-10 消息与证据行为

- `POST /api/ai/tasks` 创建任务时保存用户问题。
- Chatflow `message_end` 或正常流结束时保存最终回答和 Dify message ID。
- 能识别 `metadata.retriever_resources`、`data.retriever_resources` 或 `data.retrieval_resources` 时保存证据。
- 未识别的 Dify 事件不阻断任务，也不会猜测字段。
- 同一任务同一角色只保存一条消息；Dify message ID 重复时幂等。
- 失败/停止时默认不保存部分回答。

## 6. 前端接入要求

1. 持久化任务继续使用 `POST /api/ai/tasks`，成功后使用返回的本地 `conversationId`。
2. SSE 使用 `fetch + ReadableStream`，请求头携带 `token`；不要使用无法设置自定义 Header 的原生 `EventSource`。
3. 会话消息第一页返回最近消息，页内按时间正序排列。
4. 不向前端暴露 Dify API Key 或 Dify conversation ID。
5. 附件暂不进入历史消息持久化，前端不要依赖附件字段。

## 7. 2026-08-24 本地 HTTP 验收

- `GET /` 返回 HTTP 200。
