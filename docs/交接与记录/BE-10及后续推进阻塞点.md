## 三、仍存在的技术阻塞点

### 1. 云 MySQL 尚未完成 BE-11 迁移验证（高）

BE-11 新增 `ai_conversation` 表。云库必须先执行并验证：

```text
sql/migrations/20260824_be11_ai_conversation_up.sql
sql/migrations/20260824_be11_ai_conversation_verify.sql
```

在迁移完成前，云端新的会话列表、消息历史、重命名、删除和依赖会话表的任务创建不能视为可用。此项需要运维或可访问云 MySQL 的同学执行，后端本地不能代替云端确认。

### 2. 云端 Redis/后端实例需要重新做真实链路验收（高）

本地代码测试使用 Mock，不代表云端 Redis、Token 和异步执行线程正常。需要在目标后端环境验证：

1. 登录能写入 `token:<token>`。
2. 二次登录旧 Token 返回 401、新 Token 可访问受保护接口。
3. 创建任务后事件能持续写库并通过 SSE 返回。
4. 前端断线重连时 `Last-Event-ID` 能继续收到后续事件。

当前没有把真实 Token、Key 或用户数据写入仓库的操作计划。

### 3. 算法/Dify 真实事件样例仍缺失（中高）

后端已有兼容解析，但最终验收仍需要算法提供脱敏样例：

- Chatflow `message_end`：最终回答、Dify message ID、usage 路径。
- 检索事件：来源标题、URL、片段、相关度的实际字段路径。
- Workflow `workflow_finished`：最终展示文本、task ID、usage 路径。
- 失败、超时、429 事件及其状态码/错误字段。

没有这些样例，BE-10 的基础消息保存可以继续测试，但证据字段和 BE-13 用量/费用字段只能算“按常见格式兼容”，不能完成真实联调验收。工作区内没有可直接读取的独立 Dify 配置仓库或最新算法提交，因此不能擅自猜测字段。

### 4. 教师统计的数据范围尚未确认（中）

BE-13 当前按登录用户的 `user_id` 过滤模型调用日志。需要确认教师端最终要求是：

- 只看教师自己的调用；
- 查看自己班级学生；
- 查看全部学生；
- 由班级或学生参数筛选。

在范围确认前，不应把现有接口宣传为“全体学生统计”，也不应直接修改查询权限。

### 5. 附件是否进入历史消息仍未最终冻结（中）

前端已经可以上传文件并把 `fileId` 放入任务输入；当前后端支持文件上传，但历史消息附件持久化仍按延期方案处理。若本阶段要求在历史会话中还原附件，需要另行确定附件表或 JSON 字段；若不要求，前端应只把附件当作本次任务输入，不依赖历史附件字段。
