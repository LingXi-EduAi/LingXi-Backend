## 2. 系统边界

- 前端负责页面、路由、Vuex 状态、SSE 消费和用户交互，不持有 Dify API Key。
- 后端负责认证、资源所有权、业务接口、AI 任务状态机、Dify 代理、持久化、限流和隐私审计。
- Dify/算法组负责 Chatflow、Workflow、知识库、Agent 编排及真实事件样例，不直接修改前后端主链路代码。
- MySQL/Redis/Nginx/部署属于运行验收边界，问题需标注为环境问题或代码问题，不能混写。

## 3. 当前能力事实

### 后端

- AI 任务支持创建、快照、事件查询、SSE、停止、断线恢复和失败子任务重试。
- 已有 `ai_conversation`、`ai_task`、`ai_subtask`、`ai_event`、`ai_message`、`ai_evidence`、`ai_model_call_log`、`ai_config`、`ai_audit_log` 相关模型和迁移。
- 已提供会话管理、文件上传、模型调用日志导出、AI 配置、隐私清理和限流相关接口。
- 旧 `/api/*`、`/conversation/*` 和新 `/api/ai/*` 接口并存；兼容接口只做必要维护，新功能优先进入新 AI 链路。

### 前端

- 已有 AI 工作台、会话列表、聊天对话框、认知轨迹、子任务、证据面板、任务回放和教师 AI 分析页面。
- 已有 Vuex AI 状态与动作、SSE 解析器、上传、脱敏和相关 Vitest 测试。
- `TeachingAssistant.vue` 为学生入口兼容页面；核心状态和交互逻辑归 AI store、AI 组件和后端契约管理。

## 5. 推进阶段

1. **基线阶段**：保持两个 `master` 干净，更新任务状态、契约索引和运行版本。
2. **安全与验证阶段**：完成 Token 请求头、密钥扫描、权限测试、后端测试、前端 lint/build/test。
3. **AI 主链路阶段**：联调任务、SSE、会话历史、刷新恢复、停止/重试、消息与证据展示。
4. **演示与增强阶段**：演示数据、模型日志分析、Dify 知识库/工具、反思反馈、云部署和比赛材料。

进入下一阶段的条件是上一阶段的验收证据已提交到任务卡或交接记录。

## 6. 协作和质量门禁

- API、`LingXiEvent`、数据库迁移先冻结契约，再实现代码。
- 跨仓库功能拆为后端、前端、联调三个任务，并在联调记录中固定提交号。
- 主分支只接受可构建、可测试、可回滚的提交；临时实验使用独立分支。
- 任务完成必须同时更新代码、测试、任务卡和运行证据。
- 合并前执行：后端 `mvn clean test`；前端 `npm run test:unit`、`npm run lint`、`npm run build`。
- 静态检查不得出现 Dify Key、硬编码用户或 URL 查询参数 `token=`。

## 7. 外部输入和当前待决事项

- 算法组需提供 `ALG-01` 至 `ALG-07` 的真实 Chatflow/Workflow 事件、引用、usage、错误和限流样例。
- 部署人员需执行新增迁移的 `up` 与 `verify`，并记录云端 MySQL 结果。
- 附件字段、教师日志可见范围、数据保留期限等需求必须先形成决策记录，再修改接口或 DDL。
- Redis、MySQL、Dify 未启动属于运行环境阻塞，不得作为代码完成的替代证明。

## 8. Git 操作约定

```powershell
git switch master

git status --short --branch
```
